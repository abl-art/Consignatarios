# Cosechas (A/B de cohortes custom) — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Pestaña "Cosechas" en /finanzas: cohortes de ventas definidas a mano (nombre, rango de fechas, filtros, límite N), membresía congelada en Supabase, comparadas con vintage, PD por cuota, madurez y curva de evolución a igual edad.

**Architecture:** Lógica pura testeada en `lib/cosechas.ts`; server actions en `lib/actions/cosechas.ts` que resuelven la membresía contra la réplica (queries parametrizadas) y la congelan en la tabla Supabase `cosechas`; métricas on-demand reutilizando `fetchVintageAnalysis`/`fetchPDIndicadores` extendidas con `orderIds`; UI cliente `CosechasTab` + `CosechaForm` integrada a FinanzasTabs con permisos.

**Tech Stack:** Next.js 14 (server actions), pg (pools `getPool()` réplica / `getSupabasePool()`), Recharts, Tailwind, vitest.

**Spec:** `docs/superpowers/specs/2026-11-18-cosechas-design.md`

## Global Constraints

- Nada de Cosechas entra al `Promise.all` de `app/(admin)/finanzas/page.tsx`; en el page load solo `listarCosechas()` (query barata a Supabase), después del Promise.all.
- La base directa de GOcuotas (`getGocuotasPool`) NO se toca; todo contra la réplica (`getPool`) y Supabase (`getSupabasePool`).
- Ids de cosecha en queries SIEMPRE con `= ANY($n::text[])` parametrizado — nunca interpolación de strings.
- `MAX_ORDENES_COSECHA = 10000`; ventana de incobrable importada: `DIAS_INCOBRABLE` de `@/lib/incobrabilidad` (90).
- Originación = `order_created_at` en hora ART: `(o.order_created_at AT TIME ZONE 'America/Argentina/Buenos_Aires')::date`, rango inclusive.
- Universo = `o.order_delivered_at IS NOT NULL AND o.order_discarded_at IS NULL` en toda query de membresía y métricas.
- Montos = `SUM(i.installment_amount)` en todos lados; etiqueta UI "Monto financiado".
- UI estilo Finanzas: tablas compactas `text-xs`, botones `bg-gray-900`, tarjetas `bg-white border border-gray-200 rounded-xl p-4`; tab id `cosechas`.
- Fechas en funciones puras como strings `YYYY-MM-DD`; diferencias de días vía `Date.UTC` (nunca `new Date('YYYY-MM-DD')` local).

## Review Focus

Modos de falla que el spec implica; cada uno con su test pinneado:

1. Cosecha muy joven sin ninguna cuota vencida → curva sin puntos y PD vacío, jamás NaN; madurez muestra 100% por vencer. → Task 1, tests de `curvaEvolucion`/`resumenMadurez`.
2. Orden con contracargo cuyas cuotas figuran cobradas → la curva debe contarlas impagas (consistencia con vintage). → Task 1, test de `curvaEvolucion` con `cb: true`.
3. Todas las cuotas descartadas (o todas las órdenes anuladas post-congelado) → métricas en 0 sin división por cero; badge "N anuladas". → Task 1 test con todas `descartada: true`; Task 5 render del badge.
4. Límite mayor que las disponibles, o rango sin ventas → `aplicarLimite` devuelve todas; `crearCosecha` con 0 órdenes devuelve `{ok:false}`. → Task 1 test de `aplicarLimite`; Task 4 guard.
5. Inputs inválidos: nombre vacío, `fechaDesde > fechaHasta`, límite <1 o >10000 → error claro antes de tocar la base. → Task 1, tests de `validarDefCosecha`.

```ts
export const MAX_ORDENES_COSECHA = 10000
export const PASO_CURVA_DIAS = 7
export const COBERTURA_MINIMA = 0.5
export const ESTADOS_TRUSTONIC = ['active', 'locked', 'ready_for_use', 'idle', 'released', 'returned'] as const

export interface FiltrosCosecha {
  canal: 'total' | 'propia' | 'terceros'
  merchantId?: string
  storeId?: string
  segmentoLetra?: string
  segmentoNumero?: string
  bloqueo?: 'knox' | 'motosafe' | 'dlc'
  trustonic?: string[] // estados elegidos; undefined/[] = todos
  modelos?: string[]   // labels normalizados elegidos; undefined/[] = todos
}
export interface DefCosecha {
  nombre: string
  fechaDesde: string // YYYY-MM-DD
  fechaHasta: string
  filtros: FiltrosCosecha
  limite: number | null
}
export interface Cosecha extends DefCosecha {
  id: string
  cantOrdenes: number
  cantDisponibles: number
  montoTotal: number
  createdAt: string
}
export interface CuotaCosecha {
  orderId: string
  venta: string // YYYY-MM-DD (order_created_at ART)
  due: string
  collected: string | null
  descartada: boolean // installment_discarded_at IS NOT NULL
  cb: boolean // la orden tiene contracargo
  amount: number
}
export interface PuntoCurva { edadDias: number; pctImpago: number; cobertura: number }
export interface MadurezCosecha {
  montoTotal: number; montoPorVencer: number; pctPorVencer: number
  finCiclo: string | null; diasRestantes: number
  edadDias: number; primeraVenta: string | null; ultimaVenta: string | null
}
export type CosechaVintage = Omit<VintageRow, 'origination_month'>
export interface GrupoModelo { label: string; variantes: string[]; n: number }

export function validarDefCosecha(def: DefCosecha): string | null // null = ok, string = mensaje de error
export function aplicarLimite<T>(items: T[], limite: number | null): T[]
export function agruparModelos(filas: { model: string; n: number }[]): GrupoModelo[]
export function agregarVintage(rows: VintageRow[]): CosechaVintage
export function curvaEvolucion(cuotas: CuotaCosecha[], hoy: string, pasoDias?: number): PuntoCurva[]
export function resumenMadurez(cuotas: CuotaCosecha[], hoy: string): MadurezCosecha
```

Contratos que los tests fijan:
- `validarDefCosecha`: error si nombre vacío/solo espacios, fechas no `YYYY-MM-DD` o `fechaDesde > fechaHasta`, o `limite != null` fuera de `[1, MAX_ORDENES_COSECHA]`.
- `aplicarLimite`: `limite null` o ≥ length → mismas filas; si no, primeras `limite` (el caller ya ordenó cronológico).
- `agruparModelos`: agrupa por `normalizarModelo(model)`; `label` = variante con mayor `n` (empate → alfabético); `n` = suma del grupo; orden por `n` desc.
- `agregarVintage`: suma todos los `amt_*` de las filas; recalcula cada `pct_*` = amt/total×100 redondeado a 2 decimales; total 0 → todos 0.
- `curvaEvolucion`: descarta `descartada`; `cb` ⇒ tratar `collected` como null. Para cada orden, edad = días entre `venta` y `hoy`. Puntos en `d = paso, 2·paso, …` hasta la edad máxima entre órdenes. En cada `d`: solo órdenes con edad ≥ `d` (cobertura = esas órdenes / total de órdenes activas); vencido = cuotas con `due ≤ venta + d`; impago = vencido sin `collected ≤ venta + d`. `pctImpago` = impago/vencido×100 (2 dec). Punto omitido si vencido = 0 o cobertura < `COBERTURA_MINIMA`. (`cobertura` = 1 marca el tramo sólido del gráfico.)
- `resumenMadurez`: sobre cuotas no descartadas. `montoPorVencer` = `due > hoy`; `pctPorVencer` 2 dec (0 si total 0); `finCiclo` = max(`due`) + `DIAS_INCOBRABLE` días (null sin cuotas); `diasRestantes` = max(0, hoy→finCiclo); `edadDias` = edad de la **orden más joven**; `primeraVenta`/`ultimaVenta` = min/max `venta`.

- [ ] **Step 1: Implementar resolución de membresía** (helper interno `resolverMiembros(def)` compartido por preview/crear):
  - Valida con `validarDefCosecha`; error → `{ok:false}`.
  - Canal/merchant/segmento/bloqueo/store → `resolverFiltro(def.filtros)` (mismo shape que `FiltroIndicadores`) → `sqlCondicionClientes` + `sqlFiltrosIndicadores`.
  - Query a la réplica (parametrizada; las condiciones de clientes/bloqueo/store/segmento vienen de los helpers whitelisted existentes):

```sql
SELECT o.order_id::text AS order_id
FROM gocuotas_orders o
[JOIN marca de sqlFiltrosIndicadores si hay bloqueo]
WHERE o.order_delivered_at IS NOT NULL AND o.order_discarded_at IS NULL
  AND <condClientes> <extra.where>
  AND (o.order_created_at AT TIME ZONE 'America/Argentina/Buenos_Aires')::date BETWEEN $1 AND $2
  [AND EXISTS (SELECT 1 FROM devices d WHERE d.order_id = o.order_id::text AND d.trustonic_status::text = ANY($n))]
  [AND EXISTS (SELECT 1 FROM devices d WHERE d.order_id = o.order_id::text AND d.model = ANY($m))]
ORDER BY o.order_created_at ASC
```

  - Filtro de modelos: labels elegidos → variantes crudas vía `agruparModelos` sobre `SELECT model, COUNT(*) AS n FROM devices WHERE model IS NOT NULL GROUP BY 1` (lo mismo que sirve `getOpcionesCosechas`).
  - `disponibles` = filas; `seleccionadas` = `aplicarLimite(filas, def.limite)`; si `seleccionadas.length > MAX_ORDENES_COSECHA` → `{ok:false, error}` pidiendo límite o rango menor; 0 órdenes → `{ok:false}`.
  - `montoTotal` = `SELECT COALESCE(SUM(installment_amount),0) FROM gocuotas_installments WHERE order_id::text = ANY($1::text[])` sobre las seleccionadas.
- [ ] **Step 2: Implementar `previewCosecha`** (devuelve los números sin escribir) y **`crearCosecha`**: `requierePermiso('finanzas', 'cosechas', 'operar')`, resuelve miembros e inserta en `cosechas` (INSERT parametrizado, filtros como jsonb) devolviendo la fila mapeada a `Cosecha`. **`listarCosechas`** (SELECT orden `created_at DESC`, sin `order_ids` en el payload al cliente — pesa; mapear el resto) y **`borrarCosecha`** (guard operar + DELETE por id).
- [ ] **Step 3: Implementar `fetchMetricasCosechas`**: lee las cosechas por ids de Supabase (acá sí con `order_ids`); para cada una, **secuencialmente** (no saturar el pool de la réplica):
  - `fetchVintageAnalysis(CLIENTES_TODOS, undefined, orderIds)` → `agregarVintage(rows)` (el filtro de clientes ya viene horneado en la membresía).
  - `fetchPDIndicadores(CLIENTES_TODOS, undefined, orderIds)` → `.resumen`/`.maxCuota`.
  - Query de cuotas crudas para curva/madurez (misma guard de delivered/discarded):

```sql
SELECT o.order_id::text AS order_id,
       to_char(o.order_created_at AT TIME ZONE 'America/Argentina/Buenos_Aires', 'YYYY-MM-DD') AS venta,
       to_char(i.installment_due_at, 'YYYY-MM-DD') AS due,
       to_char(i.installment_collected_at, 'YYYY-MM-DD') AS collected,
       (i.installment_discarded_at IS NOT NULL) AS descartada,
       i.installment_amount AS amount
FROM gocuotas_installments i
JOIN gocuotas_orders o ON o.order_id::text = i.order_id::text
WHERE o.order_id::text = ANY($1::text[])
  AND o.order_delivered_at IS NOT NULL AND o.order_discarded_at IS NULL
```

  - `cb` = pertenencia a `fetchOrderIdsConContracargo()` (una sola vez para todas las cosechas, Set en JS); `hoy` = fecha ART actual → `curvaEvolucion(cuotas, hoy)` y `resumenMadurez(cuotas, hoy)`; `ordenesActivas` = DISTINCT order_id del resultado.
