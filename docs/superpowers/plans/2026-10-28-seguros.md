# Seguros por Robo — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Página /seguros que emite certificados de seguro de robo por cada venta propia con IMEI, exporta el Excel del broker, controla prima/resultado mensual y gestiona siniestros con formulario público de denuncias.

**Architecture:** Certificados persistidos en Supabase (correlativo asignado por función SQL con advisory lock), alimentados por un sync idempotente (cron diario + carga de página) que lee ventas/IMEIs/anulaciones de la réplica GOcelular y contracargos de la base directa. Lógica pura testeada en `lib/seguros*.ts`; el Excel y los datos de factura se arman en vivo. Formulario público con token (patrón /catalogo) que sube la denuncia a un bucket privado y avisa a Yami por mail.

**Tech Stack:** Next.js 14 (App Router) + Supabase (tablas + storage) + pg (réplica/base directa) + vitest + xlsx + nodemailer (lib/mailer.ts existente).

**Spec:** `docs/superpowers/specs/2026-10-28-seguros-design.md`

## Global Constraints

- Tests: `npx vitest run` — la suite completa debe quedar en verde en cada commit (hoy ~835 tests).
- NUNCA `NOT IN`/exclusión en la base directa de GOcuotas (`getGocuotasPool`); la fecha de venta es `gocuotas_orders.order_created_at`, NO `created_at` (réplica).
- Lógica pura en `lib/` con tests en `__tests__/`; fetchers sin test (patrón repo); actions con `'use server'` + `createAdminClient` de `@/lib/supabase/admin`.
- Toda ruta admin nueva se cataloga en `lib/permisos-catalogo.ts` (el test de cobertura falla si no).
- SQL en Supabase: ejecutar vía pooler `aws-1-us-west-2.pooler.supabase.com:5432`, user `postgres.rnjxmmcsxmyaktseegvt` (el host directo `db.*` es IPv6-only; ver `scripts/run-sql.mjs`).
- Encabezados del Excel broker EXACTOS, incluidos espacios finales: `N° certificado `, `Tipo `, etc. (ver Task 6).
- Suma asegurada = costo sin IVA × **1,10**; vigencia = fecha de orden + **9 meses**; prima default **2**%/mes; ingreso default **3**%/mes sobre el costo congelado.
- Deploy: `npx vercel --prod` (git push no deploya).

## Review Focus

1. DNI tipeado con puntos/espacios/cero inicial en el formulario público debe matchear igual → test de `normalizarDni` en Task 2 y uso en Task 8.
2. Venta con retiro en sucursal (sin `shipping_street`) debe emitir certificado con el domicilio de la sucursal, nunca romper el export → test en Task 2.
3. Orden con asignación vieja desvinculada + relink (cambio por garantía) debe actualizar el IMEI del certificado existente, nunca crear un segundo certificado → test de `novedadesDeCertificados` en Task 2.
4. Cambio de % con vigencia: los meses anteriores al cambio devengan con el % viejo → test de `devengoMensual` con dos tramos en Task 5.
5. Fin de vigencia con overflow de día (31/5 + 9 meses) debe caer en el último día del mes destino, no rodar al mes siguiente → test de `sumarMeses` en Task 2.
